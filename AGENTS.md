# Правила проекта

## Последовательная реализация

- Источник требований и приёмки — `PLAN.md`, утверждённый пользователем.
- M1 принят пользователем. M2–M5 выполнять последовательно автономно: проверки,
  критический review, Progress log, отдельный коммит и переход к следующему этапу.
- После M5 выполнить независимый технический аудит и устранить Critical/Major.
- M6 подготовить локально; публикация требует отдельного подтверждения пользователя.
- Если пользователь явно меняет объём или последовательность, следовать его указанию.
- Не объявлять этап завершённым, если обязательные проверки не выполнены.

## Архитектура

- React + Vite + TypeScript, Tailwind, TanStack Query, Fetch, MSW, localStorage.
- UI не импортирует MSW/repository и не обращается к localStorage напрямую.
- Application управляет формой, запросами и мутациями; domain содержит чистые правила.
- Domain не зависит от React, HTTP и браузерного хранилища.
- MSW самостоятельно проверяет запрос и актуальные данные, независимо от UI.
- Repository читает, проверяет и записывает snapshot синхронно, без `await` между шагами.
- API client проверяет ответы как `unknown`; TypeScript не заменяет runtime-валидацию.
- Не добавлять сервер, БД, авторизацию или библиотеки без конкретной необходимости.

## Инварианты бронирования

- Локальные даты `YYYY-MM-DD`, время `HH:mm`; не получать дату через UTC-обрезку.
- Минуты от начала суток, полуоткрытые интервалы `[start, end)`.
- 09:00–18:00, длительность 30–120 минут; касание допустимо, пересечение запрещено.
- Нет обязательной сетки 30 минут; ввод допускает каждую минуту.
- POST/PATCH проверяют итоговый интервал относительно свежего подменяемого Clock.
- При PATCH исключать собственный id, проверяя остальные брони целевой даты.
- Одна выбранная дата для формы, расписания и payload; refetch не сбрасывает черновик.
- HTTP 409 сохраняет поля и обновляет список. Ошибка GET не отменяет успех мутации.
- После успешной записи повтор загрузки отправляет только GET, без повторной мутации.

## Проверки и отчётность

- Использовать npm и lockfile; Node указан в `.nvmrc`.
- После кода: `npm run typecheck`, `npm run lint`, `npm run build` и тесты этапа.
- Только M1 допускает `npm run test:run -- --passWithNoTests`.
- Начиная с M2 отсутствие ожидаемых тестов не считается успехом.
- Изолировать Storage, QueryClient и Clock в тестах; не трогать пользовательские данные.
- Фиксировать фактические команды и результаты, не выдавать планируемые проверки за выполненные.
- Разделять локальное доказательство, браузерную проверку сборки и deployed demo.
- Не публиковать исходники или demo до review готового результата и подтверждения.
- Не восстанавливать AI-переписку искусственно. Сохранять только реальную историю.
- Не создавать дополнительные Skills и не делегировать агентам без запроса пользователя.
