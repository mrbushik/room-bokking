# Бронирование переговорной

Демонстрационное SPA для одной комнаты. React + Vite + TypeScript, Tailwind CSS,
TanStack Query, Fetch, MSW; Vitest + React Testing Library.

**M1 — настройка проекта — реализован и готов к review.** Есть стартовая страница и tooling.
Расписание, бизнес-правила, mock API, persistence и прикладные тесты ещё не реализованы.
Следующий этап начинается только после review пользователя.

Проверены TypeScript, ESLint, production build, конфигурация Vitest (0 тестов)
и открытие dev-страницы в браузере без ошибок. Точные результаты — в Progress log.

## Запуск

Поддерживаемая ветка Node — 22.x, начиная с 22.23.2; проверенная версия указана
в `.nvmrc` (22.23.2). npm 10 или новее. Более ранние Node не поддерживаются
выбранным набором инструментов; в частности, jsdom 30 требует Node 22.22.2+.

```bash
nvm use
npm ci
npm run dev
```

Открыть URL, выведенный Vite. По умолчанию сервер слушает только 127.0.0.1.
Удалённые шрифты и внешние API для стартовой страницы не нужны.

## Проверки

```bash
npm run typecheck
npm run lint
npm run build
npm run test:run -- --passWithNoTests
```

Последняя команда разрешена только для M1: прикладных тестов ещё нет.
Она проверяет конфигурацию Vitest, а не корректность бронирований.
Начиная с M2 используются обычные прогоны с обязательными тестами:

```bash
npm run test:run
npm test
```

Vitest по умолчанию использует Node для domain/HTTP-тестов. UI-тесты будут включать
`@vitest-environment jsdom` на уровне файла; jsdom имеет origin `http://localhost/`.
Общий setup подключает jest-dom и cleanup React Testing Library.

## Сборка demo

```bash

```

Результат — `dist`. Preview служит только локальной проверке сборки.
Публикация пока не выполнялась; hosted demo и адрес репозитория ещё не подготовлены.

## Конфигурация API

`.env.development` и `.env.demo` содержат публичные значения:

```dotenv
VITE_API_MODE=mock
VITE_API_BASE_URL=/api
```

`.env.example` описывает будущую локальную конфигурацию. `VITE_*` попадают в браузерную
сборку и не должны содержать секреты. Интерпретация режима и запуск MSW появятся в M3.
Обычный `npm run build` проверяет production-сборку; для работы будущей mock demo
нужен `--mode demo`. Будущий режим `real` потребует явной конфигурации backend.

## План и ограничения

Полная спецификация, приёмка и Progress log — в [PLAN.md](PLAN.md).
Постоянные правила реализации — в [AGENTS.md](AGENTS.md).

Demo будет сохранять данные в localStorage одного origin/профиля. Это не общий
backend: синхронизация устройств и атомарность между вкладками не гарантируются.
В M6 здесь появится проверенный Fetch-сценарий настоящего HTTP 409.

Реальная AI-история будет приложена при наличии исходного экспорта или ссылки.
Отсутствующие сообщения не реконструируются. Точное время прошлых обсуждений
не измерялось; время реализации фиксируется отдельно в Progress log.
