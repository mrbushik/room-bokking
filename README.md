# Переговорная / 01

SPA для одной комнаты: дневное расписание, создание, редактирование, перенос и
удаление с подтверждением. React + Vite + TypeScript, Tailwind CSS, TanStack Query,
Fetch, MSW, localStorage. Русский интерфейс, мобильная вертикальная компоновка.

**M1–M5 реализованы. M6 подготовлен локально; проект не опубликован.**
Нет удалённого Git-репозитория и проверенной HTTPS-demo. Публикация — после
review и отдельного подтверждения пользователя. Фактические проверки и время:
[PLAN.md](PLAN.md); аудит: [docs/REVIEW.md](docs/REVIEW.md).

## Локальный запуск

Node 22.x от 22.23.2, npm 10+. Проверенная версия — `.nvmrc`.

```bash
nvm use
npm ci
npm run dev
```

Открыть [http://127.0.0.1:5173](http://127.0.0.1:5173).
Vite может выбрать следующий порт, если 5173 занят; фактический URL — в терминале.
Стартовый набор пустой. Для ручных проверок удобно выбрать завтрашний день.
Внешние API, аккаунты и удалённые шрифты не нужны.

Production demo локально:

```bash
npm run build -- --mode demo
npm run preview -- --port 4173 --strictPort
```

Открыть [http://127.0.0.1:4173](http://127.0.0.1:4173).
`dist` — самостоятельный статический артефакт. `npm run build` без demo —
проверка production toolchain; при отсутствии API-конфигурации приложение
покажет явную ошибку запуска. Для рабочей mock-сборки нужен `--mode demo`.

## Использование и правила

1. Выбрать дату; расписание и форма используют один день.
2. Задать начало и окончание, при желании название; создать бронь.
3. Выбрать запись в расписании для редактирования. Смена даты переносит выбранный id;
   перед сохранением отображается целевой день. «Отмена» очищает форму.
4. Удаление требует подтверждения. Исторические записи доступны для просмотра и удаления.

Дата выбирается нативным полем. Время можно ввести текстом в 24-часовом формате
`ЧЧ:ММ` (или четырьмя цифрами) либо выбрать в двух независимых прокручиваемых
колёсах часов и минут. Выбор применяется только кнопкой подтверждения.
Tab/Shift+Tab перемещают фокус, стрелки открывают picker из поля и меняют выбор
в колесе; Home/End и PageUp/PageDown также поддерживаются. Escape закрывает picker
без применения. При resize или смене ориентации picker закрывается с возвратом
фокуса в поле; подтверждённое время сохраняется. Его можно открыть снова.
Остальные кнопки доступны через Enter/Space.
Ошибки связаны с полями, после ошибки фокус переходит к первому неверному полю.

- Рабочее время 09:00–18:00; длительность 30–120 минут включительно.
- Любая минута: 09:10–09:40 допустимо. Обязательной сетки 30 минут нет.
- Интервалы `[start,end)`; 10:00–11:00 и 11:00–12:00 соседствуют без конфликта.
- Итоговое начало POST/PATCH не раньше now, включая секунды/миллисекунды.
  После 17:30:00.000 новый минимальный интервал сегодня уже не помещается.
- При редактировании собственный id исключается из конфликтов; проверяется целевой день.
- Даты/время локальные, пояс браузера показан на странице. Часы обновляются раз
  в секунду и при возвращении; выбранная дата не переключается в полночь.
- Прошедшую бронь можно перенести в будущее; сохранить её прошлое начало нельзя.

Все правила проверяются mock API повторно, независимо от UI.
Ошибка мутации сохраняет введённые поля. При успехе записи и ошибке последующего
GET одновременно показаны успех и предупреждение; «Обновить расписание» повторяет
только GET. Повторов мутаций и optimistic updates нет. Старые данные при сбое GET
видны с предупреждением; paused-запрос отмечается как ожидающий сеть.

## Настоящий HTTP 409 — воспроизводимый сценарий

Выполнять в **консоли той же вкладки с приложением**, в mock-режиме.
Выбрать пустой будущий день, заполнить форму 10:00–11:00 и название, не отправлять.
Выполнить:

```js
(async () => {
  const date = document.querySelector('#booking-date').value;
  const response = await fetch('/api/bookings', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      date, start: '10:30', end: '11:00', title: 'Конкурирующая бронь'
    })
  });
  const body = await response.json();
  console.log('Ожидается 201:', response.status, body);
})();
```

1. Убедиться в **201**. Не перезагружать страницу, не нажимать «Обновить расписание».
2. Отправить исходную форму: API возвращает **409**; это проверка актуального
   Storage обычным handler, а не заранее подставленная ошибка.
3. Убедиться: виден конфликт и конкурентная бронь; все поля формы сохранены.
4. Исправить время на 11:00–12:00, сохранить успешно.
5. Удалить обе тестовые записи через UI с подтверждением.

Focus-refetch расписания отключён, polling отсутствует; часы при focus работают.
Автотесты воспроизводят аналогичный устаревший POST и PATCH вторым API client.
Отдельной панели конкурирующего пользователя нет (P1).

## Слои и HTTP

`ui → application → domain / api → Fetch → MSW → domain / repository → Storage`.
Composition root — `app/bootstrap` и `main`. UI/application/API не импортируют
MSW/repository; domain не зависит от React. Контракты — `src/api/contracts.ts`,
правила — `src/domain`, обработчики — `src/mocks/handlers.ts`.

| Метод | Путь | Ответ |
| --- | --- | --- |
| GET | `/api/bookings?date=YYYY-MM-DD` | 200 `{data: Booking[]}`, по началу |
| POST | `/api/bookings` | 201 `{data: Booking}` |
| PATCH | `/api/bookings/:id` | 200 `{data: Booking}` |
| DELETE | `/api/bookings/:id` | 204 без тела |

Booking: `id`, `date`, `start`, `end`, необязательный `title` (строки).
POST требует date/start/end; PATCH — непустое подмножество четырёх полей,
сливаемое с актуальной записью. Неизвестные поля запрещены, id неизменяем.
`title: ''` очищает название; края обрезаются, лимит длины не вводится.
Ошибка: `{error:{code,message,fieldErrors?}}`. Статусы: 400 DTO/JSON/query,
415 Content-Type, 422 правила, 404 отсутствующая запись, 409 конфликт,
500 Storage/internal. Runtime-ответы проверяются клиентом как unknown.

## Конфигурация и ограничения demo

`.env.development` и `.env.demo` содержат только публичные значения:

```dotenv
VITE_API_MODE=mock
VITE_API_BASE_URL=/api
```

В mock-режиме использовать `/api`; перед первым запросом ожидается `worker.start()`.
Ошибка регистрации блокирует приложение и даёт повтор запуска, без fallback к backend.
Service Worker требует HTTPS или localhost. Блокировка SW/Storage браузером может
мешать demo. MSW закреплён на **2.15.0**: в 3.0.3 при длительной браузерной проверке
терялась активация worker. Механизм, минимальное исправление и регрессия описаны
в [техническом аудите](docs/REVIEW.md). Worker сгенерирован CLI без ручных патчей.

Ключ `room-booking:v1` хранит версию и массив. Отсутствующий ключ означает пустой
набор; повреждение/ошибки Storage не сбрасывают данные и не дают ложного успеха.
Ручное удаление ключа безвозвратно удаляет локальные брони — обычно это не требуется.

Это демонстрация API в браузере, а не общий backend: один origin/профиль,
нет синхронизации устройств, авторизации и межвкладочной атомарности.
Проверка конфликта и запись атомарны в одной вкладке: sync read/check/write без await.
Часы браузера не являются доверенными серверными часами. Нет миграций БД.
Черновик живёт в React, не сохраняется при reload; P1-подтверждение его потери не добавлено.

Для будущего backend: `VITE_API_MODE=real`, явный `VITE_API_BASE_URL`
(абсолютный HTTP(S) или путь), тот же HTTP-контракт и при необходимости CORS.
Нужна отдельная конфигурация серверной валидации/времени/доступа. После переключения
с mock на real выполнить полный reload и проверить Network; если сохранилась
старая mock-регистрация, снять её в DevTools → Application → Service Workers.
Реальный backend интеграционно не проверялся.
`VITE_*` попадают в публичный bundle: секреты туда помещать нельзя.

## Подготовка публикации

В репозитории есть `vercel.json`: build `npm run build -- --mode demo`, output `dist`.
Поля конфигурации сверены с [документацией Vercel](https://vercel.com/docs/project-configuration/vercel-json).
Для любого статического хостинга использовать те же build/output; SW должен
отдаваться как JavaScript с того же origin, `/api/*` перехватывает MSW.

До публикации нужны: целевой Git remote, выбранный аккаунт/проект и явное
подтверждение пользователя. После публикации повторить smoke на реальном HTTPS URL,
включая worker/409/reload, и добавить URL demo/репозитория в сдачу.
